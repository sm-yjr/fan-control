## 迁移范围

主技术栈为 Rust workspace：`fan-core` 提供热模型、曲线、配置与安全策略，`fan-platform` 提供 SMC/IOKit、Unix socket、管理员安装和控制租约，`fan-app` 通过 AppKit 系统控件提供原生菜单栏体验。生产构建不调用 Swift；旧 `Sources/` 与 Swift 测试脚本暂留作迁移对照，完成兼容性和功能验收后再移除。

保留每个风扇独立的 Auto/Adaptive/Manual/Curve、硬件上下限、默认热模型与迟滞/启停策略、传感器详情、电池/电源信息、系统自动回退、睡眠多时点恢复、配置迁移、更新、键盘与 VoiceOver。新增产品目标包括可确认的执行状态、采样过期处理、所有模式的安全接管、helper 失联租约、精确曲线编辑、中文提示和可执行的故障恢复入口。

## 性能与键盘体感的实机对比

以下项目依赖本轮跳过的实机验收，全部 **本轮跳过、未验证**。产品目标包含优于系统默认的持续性能与键盘区域舒适度；“提前发出风扇命令”的模拟通过不满足这两个效果目标。首个对比应选择有风扇、已确认 SMC 范围的目标 Mac，先完成权限、归还和生命周期验收，再执行有边界的正常工作负载。

| 实验条件 | 记录与判定 |
| --- | --- |
| 同机与环境 | 固定机型、macOS、供电、室温、摆放、显示器/外设、屏幕亮度与应用版本；每轮从相近初始机身温度开始。 |
| 系统默认与智能对照 | System / Adaptive 随机交替，每个工作负载至少重复三轮；覆盖 CPU 持续、GPU 持续、混合与交互输入，避免后台更新干扰。 |
| 持续负载 | 选择可复现的正常编译、渲染或计算工作，预定 30 分钟；记录每秒工作完成量与可用的频率/功耗遥测，单独比较最后 10 分钟稳定阶段，报告重复间差异。极端温度或风险状态出现时停止，不能为了补满时长继续人为加热。 |
| 提前介入 | 同步时间线包含 CPU 利用率、CPU/GPU 温度与趋势、压力、helper 请求和实际 RPM；确认高负载/趋势介入发生在严重热压力之前。 |
| 真实性能提升 | 连同噪声、功耗、实际 RPM 和表面温度披露吞吐变化；达到统计可信的持续吞吐提升且无严重回归才允许宣称优于系统默认。若该机型没有提升，照实记录可支持的收益，调整策略或声明范围。 |
| 键盘表面测量 | 使用外部温度计，在固定键盘、掌托位置以相同方式测量，记录仪器精度、室温与校准点。校准用两点与验证用测量独立，内部传感器不能替代表面实测。 |
| 38°C 目标 | 比较默认目标与用户调整的目标是否有可重复的表面响应，记录最大/稳态偏差、达到目标耗时及未能达到的环境/负载；不承诺风扇无法实现的恒温。 |
| 校准边界 | 缺失/设备不匹配/读数失效时明确停止估计；越高端不输出表面估计且保持保守散热下界，越低端停止估计并按性能策略冷却。连续升温跨过高端不能触发降速。 |
| 功能降级 | CPU 利用率不可用、GPU 仅有温度、校准越界、无有效内部参考与权限取消均有可操作反馈。无风扇机型只读，不宣称主动散热。 |
