# Widget RPM 与半圆仪表布局回归

用户在 0.5.1 的中号双风扇 Widget 看到 1,332 / 1,327 RPM 与弧线两端相交。数字、图标用固定顶部偏移叠在 Canvas 上，没有测量文字宽度或圆弧的内侧边界；中号温度与风扇区均分宽度，又把双风扇列挤得过窄。

中号双风扇为温度区分配 30% 的内容宽度，其余留给两个仪表。`FanDialLayout` 测量实际 SwiftUI 数字、单位、图标及本地化标签，`DialGeometry` 保护完整轨道和圆头描边，文字与描边保留 2 点距离。正常四位读数留在半圆内部，长读数放到弧线开口下方，优先移除分组符而不缩小数字。小号收紧模块间距，双风扇数字以 14 点封顶，腾出的高度留给半圆。未知范围/读数使用纯读数状态，不显示有范围含义的仪表弧线；数值、过期逻辑与进度计算保持原实现。

`./script/test_widget.sh` 覆盖读数契约与 144 个尺寸/文字/状态几何组合，另外独立采样完整半圆及两端，检查描边与文字矩形的距离。

`./script/render_widget_layouts.sh [输出目录]` 在不显示窗口的独立诊断进程中渲染生产 View。128 个场景覆盖 164×164 / 344×164、小/中号、单/双风扇、中英文、深浅色，以及报告值、9,999、65,535、100,000、实测零、缺失、范围未知和过期状态。每个场景保存 PNG 和实际文字尺寸，断言数字/单位/标签在仪表内，弧线不进入标签/更新时间区域。该检查已加入 macOS14/15 CI。

本次 Mac Studio macOS27.0、CLT Swift6.4 的上述检查通过，macOS14 最低部署目标的 `.appex` 构建通过 `_NSExtensionMain` 入口核验。所有图片均为明确标注的模拟读数离屏布局证据，不能替代新候选的签名、真实系统 Gallery/桌面验证。未重新注册组件、启动生产 App、读取硬件或共享快照、替换 App/helper，也未改变控制算法、签名权限或凭据。待后续批准版本与发布。
