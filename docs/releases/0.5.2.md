# Fan Control 0.5.2

本版本修复智能散热在控制权切换和唤醒恢复时可能突然停转、再恢复高转速的问题，并补充控制历史诊断。

## 修复

- 唤醒后的 0.5、2、8、20、60 秒恢复重查保留热历史、已确认目标和渐变状态，避免在已经恢复散热后重新清空控制器。
- 发现硬件已回到系统自动模式时，从本轮实测转速重新渐变接管，避免直接恢复旧的高转速目标；硬件下限、系统散热下界和紧急保护继续生效。
- 正常低负荷交还同时要求确认目标和实际转速已降到最低连续转速附近。
- helper 确认交还系统后不再清零固件目标寄存器，避免覆盖系统决策及无效写入重试。
- 诊断导出加入最多 256 条带时间戳的本地控制历史；helper 日志记录租约交还原因和租约年龄。

## 升级提示

helper 协议由 8 升级到 9。更新应用后需要通过应用内“启用 / 修复”完成正常管理员授权，才能应用新的 helper 行为；应用不会向旧协议 helper 发送控制请求。原配置、自定义曲线和智能散热偏好保留。

## 验证范围

- 本地 Rust 检查包含 279 项通过的测试，5 项实机探针默认跳过；构建、签名、独立 helper 依赖和 Sparkle 运行检查通过。
- 在一台 MacBookPro18,1、macOS 27.0.1 上完成管理员安装、实际模式回读和短时合盖—唤醒；唤醒后的 60 秒重查保持连续控制。此证据对应相同修复代码的本地 build 22，正式版本的 CI、签名、公证和公开资产以发布工作流为准。
- 原始异常日志缺少时间戳，不能唯一确认最初事件的触发源。实测唤醒后转速反馈存在约 12 秒的起转延迟；目标确认不代表转子立即达到目标。
- 多小时睡眠、其他机型、macOS 14 实际运行以及长期噪声、散热和性能对比未在本轮验证。
