# 温度传感器语义与来源

2026-10-08 的补充覆盖 Apple Silicon M1–M5 的精确 SMC 键、存储、内存、供电、气流和固件虚拟温度。所有名称仍保留对应的原始四字节 key；详情页单独显示 key，名称不再重复 key。这里只补展示语义，控制采样、SMC 写入和 helper 协议均不改变。

iSMC 固定源文件 SHA-256：`a4c2b5e2ebede1531534eecc84294c0900822440b060f72f0da95d7848ea4aa8`。许可证文件 SHA-256：`3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`。

这些开源映射属于第一手实现的工程证据，Apple 未公开逐项物理传感器定义。名称不能作为每个机型的探头位置、物理核心数量或键盘表面实测证明。

## 展示名称和控制输入的边界

`SensorGroup` 会影响 CPU/GPU 温度聚合、紧急保护以及机身体感模型；补名称时直接改变组别会改变控制行为。本次保留所有既有 `Cpu`、`Gpu` 和 `System` 成员。原先只有 key 的新条目，无论名称写 CPU、GPU、SSD、内存或供电，均继续归 `Other`，不加入 CPU/GPU 自动汇总和机身体感输入。用户已经显式选作自定义曲线输入的原始 key 不改变。

GUI 的 worker 自行打开 SMC 并执行发现/刷新；名称来自 GUI 编译进来的 `fan-platform`，不依赖旧 helper 返回的名称。本次无需更新已安装 helper 或递增协议版本。

既有 CPU 探头在来源一致时显示“能效区”“性能区”或“超级核心区”；每个原始 key 仍唯一识别该读数。这些名称表示区域，省略物理核心编号。M3 的 `Tf*` 存在来源冲突，已在 CPU 集合中的键继续使用中性“CPU 温度探头”。其他未确认的 `Tf*` 不因前缀加入 CPU/GPU 集合。

新增诊断键表只匹配显式枚举的四字节 key。iSMC 的 `%` 模板仅展开为 `0..9`，不接受任意字母后缀；来源单独列出的 `TPDA..TPDF`、`TPDa..TPDj` 等按精确键保留。芯片专用条目由 `machdep.cpu.brand_string` 的 M1–M5 代际限定。无法识别代际时只使用共通诊断表，不复用任何代际专用 CPU/GPU、内存或 SSD 表。

## 典型新增语义

| key 或明确键集合 | 展示语义 | 范围与限制 |
| --- | --- | --- |
| `TH0a`、`TH0b`、`TH0c` 等已展开数字键 | NVMe 存储温度 | 区分小写后缀，补充诊断，不加入机身体感 |
| `TPD0..TPD9` 及来源列出的字母键、`TPDX` | 供电芯片温度／最高温度 | 不宣称 SoC 核心温度 |
| `TRD0..TRD9` 及来源列出的字母键、`TRDX` | 射频供电温度／最高温度 | 不推测具体天线位置 |
| `TMVR`、`TUVR` | 内存供电温度／非核心区供电温度 | `TUVR` 仅采用来源覆盖的 M4 |
| `Th00` 等来源列出的精确小写 `h` 键 | 芯片散热器温度 | 不据 `Th` 或 `Td` 前缀扩展 |
| `Tm0p`、`Tm1p`、`Tm2p` | 内存邻近温度 | M4；`Tm0P` 是既有主板键，大写 `P` 含义不同 |
| 来源精确列出的 M1–M5 `Ts*` | SSD 探头／控制器／汇总温度 | 各代键集合不同，省略芯片或磁盘编号 |
| `TVD0..TVD9`、`TVA0..TVA9`、`TVS0..TVS9` | 虚拟芯片／环境／传感器温度 | 固件派生值，不能当作独立物理探头 |
| M5 的 `Ta00`、`Ta04` 等来源列出的精确键 | CPU 热余量（非绝对温度） | 温差指标，继续归 Other；详情页不绘制温度高低颜色条 |
| M4 的 `Ta0p` | 环境邻近温度 | 无法由它推断相邻 `Ta0*` 的语义 |

当前 SMC 读取路径仍沿用有效温度槽过滤（`1 < value < 120`），详情列表也沿用绝对温度有效性检查。本次只补语义，没有扩大读取范围；M5 已识别的 CPU 热余量降至 0–1°C 时会被原有过滤省略。因此只能说明已取得的热余量读数有明确标签，不能宣称其全范围显示或零余量显示已经验证。这些键保持 Other，不进入自动控制汇总。

## 覆盖率与验证

| 只读样本 | 原有有名称条目 | 补充后有名称条目 | 保留未知 |
| --- | ---: | ---: | ---: |
| 本机 Apple M1 Ultra，2026-10-08 的 316 项可读传感器 | 17 / 316（5.4%） | 243 / 316（76.9%） | 73 |
| 仓库 M4 Mini 的 159 项温度样本 | 24 / 159（15.1%） | 153 / 159（96.2%） | 6 |

本机样本来自 GUI 之外的只读 SMC 检查，未执行风扇写入；测试 fixture 只保存 316 个 key，不保存设备标识、温度或配置。M4 样本为仓库已有 fixture，覆盖率表示静态映射覆盖，不宣称本机是 M4 或完成跨代硬件验收。

补充表包含 199 个共通精确键；M1、M2、M3、M4、M5 专用表分别含 149、73、127、250、209 个键。部分键与原有 CPU/GPU 集合重叠时，既有控制组及优先命名规则生效。共通加代际表在 M1–M5 中新增 1729 个 `(代际, key)` 语义组合，共涉及 713 个不同的诊断 key；这些数量不代表单台机器的物理探头数。

测试覆盖四字节/ASCII/重复键检查、CPU/GPU/System 组不扩张、大小写边界、代际重用、有限后缀、M5 热余量排除，以及两份只读样本的覆盖率回归。`fan-platform` 的模拟硬件测试通过；实际 SMC 风扇写入、管理员安装或睡眠恢复不属于本次语义变更的验收证据。

## 未确认条目

本机的 `TC10..TCA3`（实际出现的四字节键）、`Td00` 等小写 `d` 键、`TB0p`／`TB1p`、`TIDP`、`TMVC`、`TSVL`、`Tc01`／`Tc02`／`Tc05`／`Tc06`，以及实际出现的 `Ta05`／`Ta06`／`Ta0D`／`Ta0E`／`Ta25`／`Ta2D`，在本次核对的来源中没有能直接套用的精确语义。详情页显示“未确认的传感器”并保留原始 key。VirtualSMC 的 `Tb0p` 对应背光控制器，不能套用到大小写不同的 `TB0p`。

M4 Mini 的 `Ta01`、`Ta05`、`Ta09`、`Ta0L`、`Ta0P`、`Ta0S` 继续保留未知。样本里它们的值相同，提示可能是固件占位或热余量；仅据该现象无法确认其单位和具体含义，不能命名成环境温度或 CPU 温度。

后续扩大控制集合或宣称具体物理位置，需要相应设备实测与明确的采样有效性验证，独立于这次展示语义补充。
